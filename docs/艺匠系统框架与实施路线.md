# 艺匠经营管理系统 · 框架与实施路线

版本：v1.1 · 2026-11-12（业务口径已定稿）  
适用：安阳艺匠全屋定制（自有工厂 + 2 家门店）  
定位：整装业务 / 全屋定制业务 / 工厂生产 / 经营总览，四块一套系统

> **v1.1 更新（2026-11-12）**：业务口径已由老板定稿，**以《业务口径定稿-v1.md》为准**，
> 原第十节待确认清单作废。主要变化：
> - 门店与工厂改为**供应商单据模式**，不再使用"内部结算价"
> - 收款节点改为 开工 30% / 水电验收 30% / 主材下单前 35% / 竣工 5%
> - 单户毛利增加设计师提成、工长提成两个可勾选扣项；净利只在月度层面核算
> - 新增《报价系统参考要点》与《工厂渠道客户档案设计》两份设计文档

## 一、先说结论：不推倒重来，做三件事

今天把仓库盘完了，你描述的功能**大部分已经存在**：

- 数据库已有 **77 张表**：报价、客户、工地、收款、成本、工厂订单、考勤、工资、出入库、固定费用、附件、权限，全都有
- 前端已有 **四大模块**：经营总览 / 整装业务 / 全屋定制 / 工厂生产
- 已有 **角色隔离**：老板、设计师、工长、厂长，界面 + 数据库双重控制
- 已有 **账号管理**：老板可在左下角「管理账号」新增账号、改角色、重置密码

所以往下要做的不是"再建一套"，而是三件事：

| 要做的事                         | 为什么                           |
| ---------------------------- | ----------------------------- |
| **理顺**：一户一号，三块共用             | 现在同一户在不同板块各建各的单，重复录、对不上、利润算不准 |
| **补缺**：报价模板、单户核算、经营看板、权限矩阵   | 已有表但口径没定死，填法不统一，看板出不来可信的数     |
| **上线**：代码修干净 → 部署 → 用真实账号跑起来 | 之前线上跑的是过时代码，改了不生效             |

### 今天已经做掉的（技术底座）

1. **根治了构建脚本的重复代码 bug**：源文件里有一行注释和构建脚本的定位标记重名，导致每构建一次就多复制一份代码，仓库里累积了 **46 份重复片段**。已改为固定骨架 + 占位符，连续两次构建产物哈希完全一致。
2. **清掉了 22.7 万字符历史垃圾**：生成文件从 7806 行降到 3268 行，28 个源文件全部只出现一次，语法检查通过。
3. **修好静态资源嵌套**：不再产生 `vendor/vendor/` 这类重复目录。
4. **发布产物与源文件完全同步**：`framework-preview.js/css` 与 `dist` 一致（仅版本号占位符不同）。
5. **已发布验收版在线站点**（链接见第十节），并推送到 GitHub 分支 `refactor/factory-modules`（提交 `6b9fc77`）。

> 这一条很关键：**以前"改了没生效 / 有 bug"，根子就在这儿**。现在这个坑填上了，后面每改一处都能真实生效。

## 二、顶层设计：一条主线 + 四个板块 + 五类角色

### 2.1 主线：一户一号，只录一次

```
线索(CRM) → 报价 → 签约[生成 AJ-2026-0118] → 生产/施工 → 收款 → 单户核算 → 经营总览
```

- 编号规则建议 `AJ-年份-流水号`，由系统自动生成，不允许手改
- 客户姓名、电话、小区、面积、合同额**只在签约时录一次**
- 整装、全屋定制、工厂三块都引用同一个编号，不再各自建单
- 每个编号带一个状态：`报价中 → 已签约 → 生产中/施工中 → 已交付 → 已结清`

### 2.2 两套账必须分开

这是你特别强调的，也是最容易算糊的地方：

| 账       | 记什么                           | 谁看          |
| ------- | ----------------------------- | ----------- |
| **店面账** | 合同额、客户收款、店面费用、工厂供应商单据计入的成本、店面毛利  | 老板 / 店面财务   |
| **工厂账** | 工厂接单金额、板材五金采购、人工、外协、固定费用、工厂净利 | 老板 / 厂长（部分） |

两块之间**不做内部转移定价**（老板 2026-11-11 定稿）：**工厂当正常供应商对待，自己出单子**，
门店上传单据 → 系统自动识别 → 计入该户材料 / 外协成本。两边各自出账、各自核算，财务完全独立。
现有 `bill-workbench.inc.js` 已有供应商、单据号与识别入账能力，在此基础上接，不重做。

### 2.3 五类角色

老板 / 店面销售 / 设计师 / 工长 / 厂长。详见第七节权限矩阵。

## 三、整装板块

### 3.1 三个端口 + 老板财务

| 端口        | 主要动作                      | 产出        |
| --------- | ------------------------- | --------- |
| **销售端口**  | 客户登记、来源与负责人、跟进、签约、客户档案    | 客户档案 + 合同 |
| **设计师端口** | 量房、整装报价、方案与图纸、报价书发给业主     | 分项报价单     |
| **工长端口**  | 工地进程、现场记录、拍照、材料/人工登记、变更上报 | 进度 + 成本凭证 |
| **老板财务**  | 应收、已支出、单户毛利、月度汇总          | 财务核算      |

### 3.2 整装报价系统（参考行业通行做法后定稿的方向）

我查了目前装企普遍采用的清单式报价结构，核心是**让每一分钱都能被核对**。建议做成"三级拆解 + 六栏必填"：

**三级拆解**

```
第一级 空间：客厅 / 餐厅 / 主卧 / 次卧 / 厨房 / 卫生间 / 阳台 / 过道
第二级 工种：拆改 / 水电 / 防水 / 泥瓦 / 木工 / 油漆 / 安装
第三级 明细：项目名称 · 单位 · 工程量 · 单价 · 工艺说明 · 材料品牌型号
```

**六栏必填**（缺任何一栏，后期就会变成扯皮）

| 栏目      | 内容                                 |
| ------- | ---------------------------------- |
| 基础信息    | 项目地址、面积口径（建筑/套内）、层高、半包/全包、报价日期与有效期 |
| 施工项目    | 按空间 × 工种逐项列出，不写"综合项目"              |
| 工程量与单位  | ㎡ / 延米 / 点位 / 项，写清预估数量与计量规则        |
| 材料规格    | 品牌 + 系列 + 型号 + 规格，辅料同样写，不写"同档次"    |
| 单价与合价   | **人工费与材料费分开列**，管理费与税金单独列示          |
| 付款与增项条款 | 付款节点比例、增项确认与计价方式                   |

**三段式汇总**：基础工程 / 主材 / 其他费用（设计费、管理费、垃圾清运、搬运、成品保护、税费）。

**几个必须提前定死的口径**（行业纠纷高发点）：

- 墙面乳胶漆按建筑面积还是展开面积、门窗洞口扣不扣
- 水电按米还是按点位，含不含开槽封槽
- 防水墙面返高多少
- 凡以"项"计价的，备注必须写清包含的工作量与遍数

**增项单独走一条线**：增项单独立项 → 业主书面/微信确认 → 单独计价 → 不混进原合同。行业里"签约价不是最终价"的投诉，九成出在口头增项。系统里做成必走流程，比事后补单强。

**业主端报价书**：现有系统已有"业主预览 / 打印报价书"能力（简洁版 / 详细版），在此基础上把上面的三级结构套进去即可，不用重做。

> **参考视频与同类工具**：老板提供了 3 个抖音链接（1 个全屋定制报价系统、2 个「报价工坊」整装报价）。
> 抖音短链无法直接读取画面，已按视频主题 + 同类软件公开资料整理成
> **《报价系统参考要点.md》**：列出值得借鉴的做法、我们系统已有的能力、以及按优先级排的 7 项差距
> （统一工艺定额库 / 多套模板与必报项 / 五金自动测算 / 调价留痕与折扣审批 / 变更单联动应收 / 报价书完善 / 有效期提醒）。
> 待老板补发关键界面截图后再细化到字段与布局。

### 3.3 客户档案

- 复用已上线的**艺匠客户经营系统（CRM）**&#x7BA1;"签约前"：线索、跟进、高意向、防流失预警、批量导入、审批
- 新系统管"签约后"：合同、报价、工地、收款、成本、利润
- 衔接键：**客户手机号 + 项目编号**。签约时从 CRM 带出客户资料，自动生成档案，不重录
- 短期不合并两套后端（风险大、要重录数据）；等主线跑顺后再评估是否统一账号

### 3.4 工地进程管理

进度节点直接绑收款节点，让"进度"变成"钱"：

| 节点 | 定稿比例 | 系统动作 |
| ---- | ---- | ----------- |
| 开工 | 30% | 生成应收，提醒销售 |
| 水电验收 | 30% | 工长上传验收照片后触发 |
| **主材下单前** | **35%** | 触发该笔应收，作为主材采购前置条件 |
| 竣工 | **5%** | 触发结清检查 |

> **已定稿（2026-11-11）**：四节点、合计 100%，定金不单列（算进第一笔）。
> 系统里 `[30,30,35,5]` 比例本就正确，本次只把节点名称改为老板口径
> （原「木作验收」→「主材下单前」），定制业务的分期名称保持不动以免影响历史收款匹配。
> 工长端只做"选节点 + 拍照 + 记一笔"，手机能完成，不要求回电脑填表。

### 3.5 单户财务核算（你最关心的）

在**这一户的档案里**直接看到四个数：

| 指标       | 口径                             |
| -------- | ------------------------------ |
| 合同应收     | 合同额 + 已确认增项                    |
| 已收       | 实际到账合计（挂凭证）                    |
| 已支出      | 材料 + 人工 + 外协 + 工厂内部结算 + 该户分摊费用 |
| **单户毛利** | 已收（或合同额）− 已支出                  |

另需显示：未收余额、已支出明细清单、毛利率。所有成本凭证都挂项目编号，点得开、查得到原件。

## 四、全屋定制板块

### 4.1 与整装报价的区别（两套报价，不能共用一套模板）

| 维度   | 整装报价                                       | 全屋定制报价                                                                                                |
| ---- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 计价对象 | 空间 × 工种 × 工程量                              | 柜体 × 板材 × 五金 × 延米/投影面积                                                                                |
| 核心变量 | 工程量、人工单价、主材型号                              | 柜体尺寸、板材品牌/厚度、门型、五金、封边、特殊工艺                                                                            |
| 面积口径 | 建筑面积 / 套内 / 展开面积                           | **投影面积 vs 展开面积**（两种算法差价可达 30%，必须选一种写死）                                                                |
| 成本来源 | 工地材料 + 人工 + 外协                             | 板材 BOM + 五金 BOM + 外协 + 工厂加工                                                                           |
| 已有基础 | `quote-workshop.inc.js`、`reno_quote_items` | `custom-quote-workshop.inc.js`(78KB)、`board_catalog`、`hardware_bom_items`、`custom-catalog-bom.inc.js` |

系统里已经有**柜体/门板配置、投影/延米单价、基础五金包含规则、增项与特殊工艺、板材价格库**这些能力，下一步是把模板固化成"选柜体 → 选板材 → 选五金 → 自动算价 → 出报价书"的固定流程。

### 4.2 接单金额 → 工厂成本 → 中间利润

```
门店合同额（客户付的，含已确认增项）
  − 材料（含工厂供应商单据识别入账）
  − 人工
  − 外协
  − 店面费用 / 安装 / 售后
  − 〔可选〕设计师提成
  − 〔可选〕工长提成
  = 单户毛利

月度净利 = 当月各户毛利合计 − 当月固定成本（单独一项，按月核算）
```

工厂侧独立出单、独立核算，按板材/五金/人工算实际成本得出工厂毛利；门店不填「给工厂多少钱」。两边账目完全分开，各自说得清，也避免"门店说没赚、工厂说没赚"。

### 4.3 客户档案内容

用的什么板材、颜色、门型、五金品牌、封边方式、特殊备注、外协订单、图纸与变更单、安装日期、质保信息。现有系统已有订单附件、文档版本、私有存储桶能力，可直接挂。

### 4.4 工期

接单日 → 拆单/下单工厂 → 生产 → 入库 → 发货 → 安装 → 验收。每个节点有责任人和计划/实际日期，超期在总览里预警。

## 五、工厂板块

### 5.1 接单：工厂不建单，只接单

门店"已签约"自动生成工厂订单，工厂确认接收即可。这一条直接消掉重复录入和漏单。

### 5.2 工期管理

按接单中 / 生产中 / 安装中 / 已完工分类（现有已实现）。补充：每户计划交期、实际完工、超期原因。

### 5.3 单户核算

按订单归集：板材、五金、辅料、外协、计件人工、分摊固定人工 → 单户成本 → 单户毛利。板材单/五金单上传后，自动产生①这户的成本凭证 ②库存变动，不再只是"传上去存档"。

### 5.4 考勤与出入库

- 考勤明细按日期折叠，显示当天未登记员工（已有）
- 工资：月薪 / 日薪 / 计件，计件尽量归到订单；做不到先用「当月固定人工 ÷ 当月完工户数」分摊
- 库存：五金 + 辅料，**只做最低库存提醒**，不上批次/保质期那套完整 ERP——厂长嫌麻烦就会绕过系统，数据反而假

### 5.5 固定成本与利润

- 固定成本：房租、设备折旧、水电、管理人员工资、按月/按年登记（按年自动均分 12 个月，已有）
- 利润分两层看：**单户毛利**（这单赚没赚）+ **工厂月度净利**（扣完固定费用后厂子整体赚没赚），不混在一张表

---

### 5.6 渠道客户档案（新增需求）

工厂还对接装修公司等**渠道客户**（如「卓越装饰」），一个渠道下会有 5～6 个订单。
需要在工厂端建按渠道归拢的档案：点开渠道 → 看基本信息、备注时间线、该渠道全部订单与累计金额/未结/毛利，
并能直接在该渠道下新建订单、按分类筛选。

完整字段、页面结构、数据表设计、权限与验收场景见 **《工厂渠道客户档案设计.md》**。
该功能需新增 `channel_customers` / `channel_notes` 并给订单表加 `channel_id`，
**单独作为一期开发**，不与其他改动混在一起。

## 六、经营总览 · 经营看板

| 指标         | 口径                         | 来源         |
| ---------- | -------------------------- | ---------- |
| 本月订单数      | 按签约日，整装/定制分开 + 合计          | 项目主表       |
| 本月合同额      | 已签约项目的合同额合计                | 项目主表       |
| 本月毛利 / 毛利率 | 合同额 − 已归集成本                | 单户核算汇总     |
| 固定成本合计     | 店面 + 工厂分别列                 | 固定费用表      |
| **本月净利润**  | 毛利 − 固定成本 − 期间费用           | 计算         |
| 回款率        | 已收 ÷ 应收                    | 收款表        |
| 在产 / 在建单数  | 状态非"已交付"                   | 项目主表       |
| 客户数        | 本月新增 / 累计 / 高意向            | CRM + 项目主表 |
| 预警         | 超期未收款、交期延误、库存低于安全量、长期未跟进客户 | 规则引擎       |

看板按**月 / 年**切换，按**整装 / 定制 / 工厂 / 合计**分栏，点数字能下钻到具体户。
